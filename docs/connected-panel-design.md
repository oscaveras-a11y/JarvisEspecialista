# Painel conectado ao CORE — beta pessoal no GitHub
Objetivo: permitir ao proprietário criar uma investigação, enviar arquivo autorizado, executar análise e consultar resultado/relatório reais pelo painel aprovado. Execução e testes somente no GitHub; sem instalação no computador e sem login adicional da aplicação.

Arquitetura: servidor Python restrito a loopback serve os arquivos web e uma API da mesma origem. GitHub Codespaces fornece ambiente remoto e porta privada pela conta GitHub. A criação/início do Codespace fica com o proprietário, inclusive consumo de franquia; nenhum serviço ou porta pública é criado pelos agentes. Pages permanece uma demonstração estática. Dados, uploads e SQLite ficam fora do checkout/Git.

API limitada a criação de casos com pasta de uploads gerida pelo servidor; envio de arquivo até 4 MiB; análise estática, firmware, avaliação de recuperação, inventários de disco/PCAP; estado, pausa, retomada, cancelamento, execução de pendentes e relatório CORE. Nenhum caminho/comando fornecido pelo navegador é executado. Um trabalho por vez neste beta, processo CORE com limites, cancelamento persistente preservado. Upload nunca é executado como programa. Origem/Host e nonce por processo impedem mutações cross-site; isso não substitui autenticação. A privacidade do acesso depende da porta privada do Codespaces.

O frontend detecta API compatível na mesma origem. Modo conectado usa estado/auditoria do CORE e arquivos enviados; não importa casos demonstrativos, não mistura localStorage e não retorna silenciosamente ao modo fictício se a conexão cair. Modo estático original continua disponível como demonstração claramente identificada. Resultados, erros e relatório reais aparecem no painel. Recursos não ligados à API (sessões de tentativa de chaves e agentes por provedor) seguem explicitamente fora deste primeiro fluxo.

Ghidra/Binwalk são opcionais na inicialização do servidor; configuração confiável por ambiente, ausências visíveis e sem simular execução. Preparação remota separada e documentada reutiliza versões/checksums já validados no projeto. Nenhuma chave de API é exigida para analisar arquivos.

Plano: 1. Contratos HTTP e browser conectados em Actions, observar falha antes da implementação. 2. Servidor separado sem alterar CORE/CLI compartilhados. 3. Adaptador da interface, resultados e desconexão explícita. 4. Configuração Codespaces, instruções de abertura/privacidade/parada e disponibilidade das ferramentas. 5. Testar HTTP e browser Windows/Linux, manter suíte offline existente, revisar código e capturas, integrar branch própria. Validar que a árvore integrada corresponde à testada. Ativação do Codespace não será declarada como realizada sem ambiente de fato aberto.

Aceite: upload sintético produz SHA-256 calculado pelo CORE, tarefa persistida, auditoria verificada e relatório contendo o hash; pausa/cancelamento bloqueiam novos envios, casos sobrevivem à reinicialização; requisições sem nonce/origem inválida, arquivos grandes, formatos JSON inválidos e acesso ao filesystem fora da lista são recusados; o painel mostra os resultados reais e não apresenta exemplos em modo conectado.
